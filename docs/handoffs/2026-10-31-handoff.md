# PuppyPi repository bootstrap and R&D handoff

Session date: 2026-10-31. The project is now an independent local Git repository
on `main`, with the existing Teach and Find prototype preserved and an expanded
application/research roadmap. No remote was configured or content published.

## Completed work

- Initialized `.git/` inside the PuppyPi directory without changing the parent
  ECUS repository. Configured the same existing author identity locally.
- Imported the existing Python core, scripts, tests, source CAD snapshot,
  historical documents, and selected synthetic evidence.
- Added `uv.lock`, a Python 3.12 reference version, optional simulator dependencies,
  and `.venv-dev/` so the previous `.venv/` remains available.
- Added current evidence status, 32 feature entries, four research tracks,
  shared architecture, upstream reuse notes, and demo acceptance scenarios.
- Added `AGENTS.md`, `CONTRIBUTING.md`, a Makefile, local documentation checks,
  and a scoped Conventional Commit hook. The hook is enabled for this checkout;
  subsequent clones need `make hooks`.

## Commit structure

1. `chore(repo): initialize standalone PuppyPi repository`
2. `feat(core): import Teach and Find research baseline`
3. `feat(sim): preserve simulation assets and baseline evidence`
4. `docs(research): define feature roadmap and four research tracks`
5. `chore(workflow): add agent rules and commit validation`

The feature tracks are plans, not newly implemented robot capabilities. No physical
robot mission, model download, pretrained-model inference, or new full benchmark
was run during this bootstrap.

## Validation

- Existing environment: five baseline tests passed.
- Isolated locked development environment: five tests passed.
- `make check`: focused Ruff checks, local documentation targets, commit titles,
  and current-change whitespace checks passed.
- `make test`: five tests passed, including the local relay watchdog test.
- `make build`: source distribution and Python wheel built successfully.
- Commit hook: eight accepted/rejected message cases behaved as expected.

These checks establish software/bootstrap behavior. They do not establish real
robot motion, inference accuracy on camera recordings, or optional EGL rendering.
Historical outputs have not been regenerated with the new lockfile.

## Important limitations

- The in-memory object bank has no durable timestamped history yet.
- Similarity-derived confidence is not statistically calibrated.
- The synthetic evaluator places cameras at selected views; the MuJoCo animation
  is scripted. Physical closed-loop execution still needs implementation/testing.
- Vendor CAD provenance is recorded in `assets/README.md`; its original revision
  and asset license were not captured. The Xacro snapshot is incomplete.
- Exact hardware, sensors, deadline, team size, and grading rubric remain open.
