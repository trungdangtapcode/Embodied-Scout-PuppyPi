## Important limitations

- The in-memory object bank has no durable timestamped history yet.
- Similarity-derived confidence is not statistically calibrated.
- The synthetic evaluator places cameras at selected views; the MuJoCo animation
  is scripted. Physical closed-loop execution still needs implementation/testing.
- Vendor CAD provenance is recorded in `assets/README.md`; its original revision
  and asset license were not captured. The Xacro snapshot is incomplete.
- Exact hardware, sensors, deadline, team size, and grading rubric remain open.

## Continuation: Phone Observer research scope

Added [Phone Observer](../11-phone-observer-research.md), R5, and planned features
F33–F37, bringing the inventory to 37 entries and five research tracks. The user
asked for a phone as an external viewpoint. The plan starts with a fixed phone,
not a carried camera, and focuses on localization, cross-view verification,
observation selection, and synchronized replay on PuppyPi Standard.

Reviewed primary sources and available code for external-camera robot pose
estimation (ICRA 2023), Ego-Exo4D tools, AprilTag/OpenCV, and aiortc. The ICRA method
is a research reference; an official usable implementation was not verified.
No imported code or pretrained weights were added. The document records source
links, availability/terms, sensor assumptions, calibrated geometry, timestamp
uncertainty, independent evaluation, and an adjustable 16-week allocation.

R1 + R5 are the suggested main experimental contribution; R2–R4 supply application
breadth and extensions. The phone functionality remains Planned. The current v2
database has no camera-session/calibration/clock schema and is not a fusion engine.

Next phone step: add a versioned camera/session record and a prerecorded dual-view
adapter with clock-skew, dropout, and changed-calibration regressions. Then add
phone capture and stationary physical calibration before allowing motion proposals.
Board/firmware, phone OS/model, host compute, team size, and exact grading weights
remain unverified; none blocks the offline adapter work. `make check` is the
required validation for this documentation-only extension.
