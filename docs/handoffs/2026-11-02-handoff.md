## Later user-authorized actual SAM/Cutie machine feasibility trial

Created isolated `.venv-tracking/` with Python 3.12.13, PyTorch 2.6.0+cu124 and
torchvision 0.21.0+cu124, plus inference dependencies. Installed the pinned SAM
package with optional CUDA-extension postprocessing explicitly disabled and no
build-isolation dependency upgrade. Source checkouts stay unmodified under the
ignored research directory. Downloaded and verified actual SAM tiny, Cutie
base-mega and ResNet-18/50 weights under ignored `data/models/tracking/`.

`scripts/research_tracking_probe.py` is a research-only reproducer. It calls the
original learned implementations, checks source revisions, checkpoint hashes,
exact Cutie state keys/shapes and loaded tensor agreement, and blocks socket
connections during inference. It records raw masks, source/output digests,
timings, explicit device choice and concrete failure tracebacks. It is not a
production adapter/worker or phone API and does not accept robot commands.

Actual trials:

- Initial CPU request failed because original SAM warmed a CUDA positional cache
  while GPUs were visible. Preserved error; not a CPU timing. Explicit CPU mode
  now hides CUDA before discovery/construction, without changing algorithms.
- CPU SAM + Cutie completed all 12 moving renderer frames, initialized from an
  authored box and actual SAM output. Final eight-thread FP32 run: SAM inference
  0.853 s, Cutie mean/P95 step 0.247/0.295 s, 4.05 compute-step FPS, peak RSS
  1,334 MiB. This is a tiny replay; the unchanged 5 FPS live gate is not passed.
- Original Cutie `bike` example inputs/supplied mask completed four frames on
  CPU through the same original sequential entry points, with device/output
  handling adapted. This is a supplied-mask replay, not automatic initialization
  or an unmodified CUDA example. Early four-thread trials ran concurrently and
  are labeled exploratory rather than used for the main performance statement.
- Explicit `cuda:1` trial loaded both models, then failed during SAM forward with
  physical free VRAM nearly exhausted. Own allocator cap was 768 MiB; no CPU
  retry, alternate model or substitute output. Existing GPU workloads were not
  stopped; GPU usage returned to its initial allocation snapshot afterward.
- Actual missing-weight and corrupt-checkpoint trials fail before inference with
  zero frames. They are opt-in model failure probes, separate from default tests.

The current machine can continue component work on CPU. A GPU trial needs free
capacity here or another provisioned host; no remote address or transfer was
